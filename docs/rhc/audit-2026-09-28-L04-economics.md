# L04: разбор комиссии на выигрышах LP

Дата: 2026-09-28. Основано на `contracts/test/L04FeeEconomics.t.sol`, измерено
на финальном коде после всех правок сессии (A01-A08, L01, L04). Цены газа -
самая свежая выборка, что есть (`docs/rhc/measurements/README.md`, суточный
замер 2026-09-04...05); свежее в моём распоряжении данных нет.

## Что было

Протокольная комиссия (`feeBps`) взимается только внутри `_settleOrder`'s
`won`-ветки. В PvP оба вызова `_settleOrder` происходят всегда (кто-то да
выиграл), поэтому комиссия берётся всегда. В LP-матче `_settleOrder`
вызывается один раз - только для пользователя. Если пользователь проигрывает,
эта ветка не срабатывает вообще, а банк уходит в пул отдельной строкой
(`usdc.safeTransfer(liquidityPool, m.amount * 2)`) без единого упоминания
комиссии.

## Измеренные числа (текущий код, ДО фикса)

Ставка 0.005 WETH (текущий `MIN_BET`), банк 0.01, `feeBps = 100` (1%, то же
значение, что стоит на тестнете после `applyNewFee` от 11.09).

| Исход | Газ `settleMatch`/`emergencyRefundMatch` | Доход казны |
|---|---:|---:|
| PvP, есть победитель | 158 141 | 0.0001 WETH |
| LP, пользователь выиграл | 158 186 | 0.0001 WETH |
| **LP, пользователь проиграл** | 111 937 | **0** |
| Ничья | 70 605 | 0 |
| Аварийный возврат | 46 413 | 0 |

Это газ именно `settleMatch`/`emergencyRefundMatch` (без обвязки резолвера -
чтения TWAP из пула). На живом пуле резолвер добавляет ещё ~41 500 газа на
чтение `observe()` (замерено ранее, живой пул делает бинарный поиск по кольцу
наблюдений, мок - нет). Итоговая оценка на мейннете:

| Исход | Газ (mainnet-оценка) |
|---|---:|
| PvP | ≈ 199 600 |
| LP, пользователь выиграл | ≈ 199 700 |
| LP, пользователь проиграл | ≈ 153 400 |
| Ничья | ≈ 112 100 |
| Аварийный возврат | 46 413 (без резолвера вообще) |

## Доход минус газ, по перцентилям цены газа (суточная выборка)

| Цена газа | p50 0.398 | p90 0.453 | p95 0.605 | p99 1.039 gwei |
|---|---:|---:|---:|---:|
| PvP: доход - газ | **+0.0000206** | +0.0000096 | **-0.0000208** | -0.0001074 WETH |
| LP-выигрыш: доход - газ | +0.0000205 | +0.0000095 | -0.0000209 | -0.0001075 WETH |
| LP-проигрыш (до фикса): доход - газ | -0.0000611 | -0.0000696 | -0.0000929 | -0.0001595 WETH |
| Ничья: доход - газ | -0.0000446 | -0.0000508 | -0.0000678 | -0.0001165 WETH |

**Главный вывод, которого не было в историческом разборе аудита:** даже
**PvP-сеттлмент сам по себе не гарантированно прибылен** - уже на p95
(0.605 gwei, обычный день по суточной выборке, не всплеск) казна теряет
деньги на КАЖДОМ PvP-расчёте. LP-матч с проигрышем пользователя убыточен
**на любом перцентиле**, включая p50 - это не вопрос "иногда невыгодно", а
"всегда невыгодно", если пользователь проигрывает.

При условных 50% выигрышей против LP: средний доход с LP-матча = 0.00005
WETH, средний газ ≈ 176 600 (среднее между 199 700 и 153 400). При p50
(0.398 gwei) это 0.0000703 WETH газа - **то есть LP-матч в среднем убыточен
уже при p50**, не только на всплеске.

## Фикс

`settleMatch`'s LP-ветка теперь берёт тот же `feeBps` с банка при выигрыше
LP, что и при выигрыше пользователя, до того как перевести остаток в пул.
Без реферальной комиссии с этой конкретной комиссии - реферала начисляют за
выигрыш реферала, а не за выигрыш LP за счёт чужого проигрыша, это разные
вещи, и я решила не растягивать реферальную семантику на новый случай без
отдельного продуктового решения.

После фикса LP-проигрыш даёт те же 0.0001 WETH дохода, что и PvP/LP-выигрыш
(измерено, `test_Fix_LPWin_PaysTheSameProtocolFeeAUserWinWould`). Газ на LP-
проигрыш вырос со 111 937 до 178 439 (+66 502 - лишний трансфер комиссии +
внешний вызов `distributeFee`).

**Это не решает корневую проблему**, которую фикс не может решить сам по
себе: сама ставка `feeBps=1%` на `MIN_BET=0.005 WETH` даёт слишком тонкую
маржу против измеренного газа даже без асимметрии LP. Варианты, которые
это может закрыть (ни один не реализован в этой сессии - решение продуктовое):

1. Поднять `MIN_BET` (сейчас установлен из соображений "1% банка окупает
   газ", см. `measurements/README.md` - тот расчёт использовал более старую,
   более низкую оценку газа сеттлмента).
2. Поднять `feeBps` (сейчас 100 бп из 100 бп максимума `FEE_MAX` - предела
   уже нет, некуда расти без смены константы в контракте).
3. Явный резерв/субсидия: пополнять ETH кипера из WETH-казны напрямую,
   признав, что часть сеттлментов (тай, аварийный возврат, тонкая PvP-маржа
   на всплеске газа) - операционные расходы, а не источник дохода.

Все три требуют отдельного продуктового решения, не однострочной правки.
Мера, которую этот фикс даёт прямо сейчас: казна больше не получает СИСТЕМАТИЧЕСКИ
меньше с LP-объёма, чем с PvP-объёма той же величины - асимметрия убрана,
общая тонкость маржи - нет.

## Побочная находка: ОПРОВЕРГНУТА 2026-09-29

Здесь раньше стояло утверждение, что только что созданный рынок `PoolMarketFactory` не принимает
ни одной ставки, пока владелец LP не вызовет `authorizeMarket`, потому что `LiquidityPool.tryMatch`
ревертит для неавторизованного рынка. **Для задеплоенного стека это неверно.** `DeployRhc.s.sol`
ставит `PoolLiquidityPool`, а его `tryMatch` возвращает 0 для неавторизованного вызывающего и
ничего не трогает; ордер остаётся в стакане. Проверено тестом на настоящих контрактах
(`contracts/test/FixRegressions.t.sol`, `test_UnauthorisedMarketWithAFundedVault_StillTakesBets`:
свежий рынок без допуска, депозит в хранилище, ставка проходит, встречная ставка матчится PvP).

Утверждение выросло из тестовой обвязки: `PoolMarketFactory.t.sol` и `L04FeeEconomics.t.sol`
подключали к фабрике базовый `LiquidityPool`, который действительно ревертит. Обе сьюты теперь
подключают `PoolLiquidityPool`, то есть тот тип, который развёрнут.
