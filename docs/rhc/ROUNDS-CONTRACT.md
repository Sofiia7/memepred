## Интерфейс v3

Для кипера и фронтенда. Имена и типы - ровно такие, как в `contracts/src/PoolRounds.sol`.

**Игрок**

| Функция | Что делает |
|---|---|
| `bet(uint256 roundId, uint256 stake, uint8 side, address referrer)` | ставка `stake` WETH (нужен `approve`) на сторону `side`: 1 = UP, 2 = DOWN. Одна ставка на адрес в раунде, только в `[openAt, closeAt)`. `referrer` необязателен; нельзя сам игрок и сам контракт. Откатывается, если пул сейчас ниже гейта (`PoolTooThin`) или ставка увеличивает принятый банк сверх `глубина / depthPerBank` (`BankTooLargeForPool`). На паузе откатывается |
| `claim(uint256 roundId) returns (uint256 payout)` | неактивированный раунд: вся ставка, с `closeAt`; активированный: после расчёта, неисполненная часть плюс выигрыш. Паузой не блокируется |

**Кто угодно (кипер)**

| Функция | Что делает |
|---|---|
| `fixStrike(uint256 roundId)` | с `strikeEnd`, только активированный раунд: сохраняет средний тик `[strikeStart, strikeEnd]`. Окно уже потеряно кольцом (причина 1) или пул в окне держал меньше `банк x depthPerBank` WETH (причина 4) - сразу REFUND |
| `settle(uint256 roundId)` | с `settleAt`, только активированный: UP / DOWN / TIE / REFUND. Сбой чтения пула - откат, повторить позже. С `settleAt + 24 ч` - REFUND без чтения пула. Ликвидность пула в момент вызова значения не имеет, только ликвидность в окнах |
| `delistIfBelowGate(address pool)` | снимает пул, чья глубина ниже `gateDepth()` или кольцо ниже `minCardinality`; только новые ставки, открытые раунды доживают. Пул выше гейта - откат `PoolAboveGate` |
| `withdrawFees() returns (uint256)` | переводит накопленную долю проекта на `treasury` |
| `claimReferral() returns (uint256)` | реферер забирает начисленное |

**Чтение**

| Функция | Возвращает |
|---|---|
| `roundTimes(uint256 roundId)` | `Times { openAt, closeAt, strikeStart, strikeEnd, settleAt }` |
| `keeperDeadlines(uint256 roundId)` | `(fixStrikeBy, settleBy)`: последние секунды, до которых окно гарантированно читается даже при наблюдении каждую секунду; формулы ниже |
| `exitWindowOf(uint256 duration)` | окно выхода: `duration / 5` в границах 30-300 с |
| `roundView(uint256 roundId)` | `RoundView { pool, duration, index, times, committed, rawUp, rawDown, acceptedUp, acceptedDown, bank, minBank, costAllowance, bookClosed, activated, strikeFixed, outcome, entryTick, exitTick }` |
| `ticketOf(uint256 roundId, address player)` | `(stake, side, status)`, статус 0 нет ставки, 1 PLACED, 2 CLAIMED |
| `previewClaim(uint256 roundId, address player)` | `(payout, referralShare)`; откатывается ровно тогда, когда откатится `claim` |
| `gateDepth()` | глубина WETH, нужная для листинга и для ставок: `max(2 ETH, depthPerBank x minBank)`, 50 ETH при значениях по умолчанию |
| `maxBankOf(address pool)` | наибольший принятый банк раунда при глубине пула сейчас: `wethDepth / depthPerBank` |
| `wethDepth(pool)`, `canServeWindow(pool, window)` | то, что проверяет гейт (как в `PoolMarketFactory`) |
| `roundIdOf`, `decodeRoundId`, `currentRoundId` | `roundId = pool << 96 \| duration << 64 \| index` |
| `maxSideRatio()`, `strikePause()`, `strikeWindow()`, `minStake()`, `maxStake()`, `minCardinality()`, `depthPerBank()` | неизменяемые параметры развёртывания |
| `minBank()`, `costAllowance()`, `treasury()`, `pauser()`, `paused()`, `feesAccrued()`, `referralOwed(address)`, `pools(address)` -> `(listed, wethIsToken0)`, `durationEnabled(uint256)` | текущее состояние |
| `isMarket(address)` | `true` только для самого контракта (для нового `ReferralRegistry`) |

**Дедлайны кипера (формула, re-audit V3-5).** Кольцо листингованного пула не меньше `minCardinality` записей, Uniswap
пишет не чаще раза в секунду, значит кольцо помнит не меньше `minCardinality - 1` секунд:

- `fixStrikeBy = strikeStart + minCardinality - 1`;
- `settleBy = settleAt - exitWindow(T) + minCardinality - 1`.

При значениях по умолчанию (окно страйка 300 с, `minCardinality` 900) это `strikeEnd + 599` и для T = 300 `settleAt +
839` (T = 900: `settleAt + 719`, T = 60: `+ 869`). На тихом пуле окна живут дольше; после дедлайна оживлённый пул
может их потерять, и раунд уходит в REFUND с комиссией 1%.

**События**

`Bet(uint256 indexed roundId, address indexed player, uint8 side, uint256 stake)` (topic

**Что изменилось после повторного аудита** (для кипера и фронтенда): новое поле `Params.depthPerBank`; новые функции

## Выводы за минуту

1. **Все пункты повторного аудита, кроме информационных, внесены в код.** V3-1: правило глубины. V3-2: ликвидность
   берётся из окон через `secondsPerLiquidityCumulativeX128`, а не в момент вызова. V3-3: `delistIfBelowGate` и
   повторная проверка гейта в каждой ставке. V3-4: реестр читается низкоуровневым вызовом. V3-5: дедлайны по
   формуле. V3-6: скрипт требует кап 1. V3-7: пол `costAllowance` 2e13 и запас кольца 600 с.
2. **Правило глубины ограничивает, но не убирает выгоду сдвига цены. Это главное, что надо знать.** Банк раунда не
   больше `глубина / K`, K = 2500. Сдвиг удерживается `fee x W x x`, выигрыш манипулятора не больше `0.98 x W / K`,
   поэтому сдвиг окупается, пока `x < 0.98 / (fee x K)`. При K = 2500 это 3.9% на пуле с комиссией 1% и 13% на пуле
   0.3%, от глубины порог не зависит. Раунд, где цена иначе стояла бы, решает сдвиг на один тик; он окупается в
   392 раза. Чтобы не окупался и он, нужен K около 980 000, а это глубина 19 600 ETH при банке 0.02. Правило
   превращает неограниченную манипуляцию в ограниченную: не больше 0.98 x W / 2500 за раунд. Нестыковка в исходных
   числах: при K = 2500 сдвиг на 2% стоит не «дороже всего банка», а половину наибольшего банка.
3. **Правило сильно сужает круг пулов.** Листинг требует глубины `K x minBank` = 50 WETH вместо 2. По суточному скану
   новых пулов (`measurements/README.md`, раздел 4) таких 5 из 292 в сутки против 77 при гейте 2 ETH. Кольцо должно
   быть 900 записей; пулы, подготовленные для рынков (300), придётся доращивать.
4. **Глубина окна измеряется, а не берётся на момент ставки.** Поэтому ликвидность, добавленная ради ставки и снятая
   после (JIT, «сэндвич»), дешёвого окна не покупает: раунд с тонким окном возвращается (REFUND, причина 4). Снятая
   после окон ликвидность больше ничего не блокирует; раньше это были сутки блокировки.
5. **Газ кипера на раунд 160-217 тыс. с оценкой L1 при бюджете 1 000 000: запас в 4.6 раза.** Расчёт не зависит от
   числа игроков. Ставка подорожала на чтение глубины пула. Замер на стенд-ине: 108 007 газа, из них 23 490 - сам
   стенд-ин; на настоящем пуле, по оценке, около 92 тыс.
6. **Проверено:** 646 тестов в 51 сьюте, 0 упавших. Шесть мутаций проверок глубины и чтения реестра - каждую ловят
   от 1 до 4 тестов. 88 векторов эталона не менялись и проходят.

## Правило глубины (re-audit V3-1, V3-2, V3-3)

**Что делает контракт.**

- `bet`: глубина пула сейчас (та же формула, что у гейта) не ниже `gateDepth()`. Ставка, увеличивающая принятый банк,
  допускается, только если новый банк не больше `глубина / K`. Ставка на большую сторону банк не увеличивает и не
  ограничивается: её излишек и так возвращается без комиссии. Ограничивать сумму всех ставок я не стала: тогда один
  крупный кошелёк на одной стороне бесплатно занимал бы весь раунд и не давал второй стороне ставить.
- `fixStrike` и `settle`: глубина, которую пул держал в окне страйка и в окне выхода. Считается как средняя
  гармоническая ликвидность окна `окно << 128 / (разность secondsPerLiquidityCumulativeX128)`, тот же способ, что
  `OracleLibrary.consult` у Uniswap, в цене среднего тика окна. Она должна быть не меньше `банк x K`, иначе раунд -
  REFUND (причина 4, комиссия 1%). Окно, в котором ликвидности не было вовсе, даёт почти нулевую глубину.
- `delistIfBelowGate`: снять пул, упавший ниже гейта, может кто угодно.

**Таблица: глубина пула и наибольший банк раунда при K = 2500.**

| Глубина пула, WETH | Наибольший принятый банк раунда, ETH | Наибольший выигрыш манипулятора (0.98 x банк), ETH | Цена сдвига на 2% при комиссии 1%, ETH | Цена сдвига на 1 тик при комиссии 1%, ETH |
|---:|---:|---:|---:|---:|
| 50 (гейт при minBank 0.02) | 0.02 | 0.0196 | 0.01 | 0.00005 |
| 100 | 0.04 | 0.0392 | 0.02 | 0.0001 |
| 250 | 0.1 | 0.098 | 0.05 | 0.00025 |
| 500 | 0.2 | 0.196 | 0.1 | 0.0005 |
| 1 000 | 0.4 | 0.392 | 0.2 | 0.001 |
| 2 500 | 1.0 | 0.98 | 0.5 | 0.0025 |

Отношение выигрыша к цене сдвига от глубины не зависит. При K = 2500 оно равно 1.96 для сдвига на 2% и 392 для
сдвига на один тик на пуле с комиссией 1%. **Порог сдвига, выше которого манипуляция не окупается:**
`x* = 0.98 / (fee x K)`.

| Комиссия пула | x* при K = 2500 | K, при котором не окупается сдвиг на 2% | K, при котором не окупается сдвиг на 1 тик |
|---:|---:|---:|---:|
| 1% | 3.92% | 4 900 | 980 000 |
| 0.3% | 13.07% | 16 334 | 3 266 667 |
| 0.05% | 78.4% | 98 000 | 19 600 000 |

Модель цены сдвига взята у аудитора: объём `W x x / 2` туда и обратно, полный диапазон, без встречного потока. На
концентрированной ликвидности сдвиг дешевле. Тест `test_Economics_PriceSteering_WithTheDepthRule` проверяет обе
стороны: при `x*` сдвиг стоит весь выигрыш, ниже `x*` окупается, на один тик окупается в 392 раза.

**Остаток риска, который правило не закрывает.**

1. Сдвиги меньше `x*`, прежде всего в раундах, где цена иначе стояла бы на месте. Закрыть их можно только большим K,
   то есть почти всеми пулами меньше, или другим оракулом.
2. Единственный LP, который ставит на проигрывающую сторону, может снять ликвидность до окна или в окне. Раунд
   уходит в REFUND, и он возвращает 99% вместо 0. Пул без ликвидности цены не даёт, поэтому этот рычаг не закрыть.
   Выигрыш ограничен его принятой частью, то есть не больше банка / 2, а банк не больше W / K.
3. **Новый вид отказов:** раунд возвращается (REFUND с комиссией 1%), если глубина в окне естественно просела ниже
   `банк x K`. Например, цена ушла из диапазона концентрированных позиций. Частоту таких возвратов никто не измерял.
4. Гейт при листинге и ставках считает глубину на текущей цене, как фабрика. Концентрированная ликвидность даёт
   верхнюю оценку реальной глубины.

## Жизненный цикл

Раунд `k` пула длительности `T`, по умолчанию пауза `P = 300 с`, окно страйка `W = 300 с`:

| Момент | Время | Что можно |
|---|---|---|
| `openAt` | `k x T` | `bet` |
| `closeAt` | `openAt + T` | книга окончательна; неактивированный раунд забирается `claim` |
| `strikeStart` | `closeAt + P` | ничего: пауза |
| `strikeEnd` | `strikeStart + W` | `fixStrike` до `fixStrikeBy` |
| `settleAt` | `strikeEnd + T` | `settle` до `settleBy`: окно выхода `T / 5` (30-300 с), якорь - его последняя треть, гард 2% |

## Деньги

Без изменений против первой редакции v3: принято `min(rawUp, ratio x rawDown)` и симметрично; активация по `minBank`
и по покрытию бюджета газа 1%-й комиссией; комиссия 2% или 1% при TIE/REFUND; реферальный котёл делится по билетам
при `claim`, доля проекта начисляется при расчёте; при капе 1 победитель получает 1.96 x принятой части. Пыль меньше
3 wei на билет, её никто не выводит.

## Решения

1. **Кап - неизменяемый параметр, развёртывание только 1** (скрипт это требует).
2. **Пауза, окно страйка и K неизменяемы.** Это условия ставки, которые игрок видит до подписи.
3. **Гейт пулов**: глубина `max(2, K x minBank)` WETH, кольцо `max(окно страйка, 300) + 600`, история на самое
   длинное окно; перепроверяется в каждой ставке; снять ниже гейта может любой. Гейт следует текущему `minBank`:
   если его поднять, пулы, не дотягивающие до нового `K x minBank`, перестают принимать ставки и снимаются любым.
4. **Правило глубины проверяется на банке, а не на сумме ставок** (см. выше, защита от занятия раунда одной стороной).
5. **Глубина окон - гармоническое среднее ликвидности окна по `secondsPerLiquidityCumulativeX128`.** Этот массив
   `observe` отдаёт в том же вызове, поэтому лишнего чтения пула нет. Разность накопителя, равная нулю, от настоящего
   пула прийти не может; она читается как нулевая глубина, а не как бесконечная.
6. **Реестр рефералов читается `staticcall`** с лимитом 100 000 газа (`ReferralRegistry` нужно около 5 000).
   Копируются только первые 32 байта ответа, рабочая память обнуляется перед вызовом. Короткий ответ, не адрес,
   откат, сжигание газа - доля идёт в казну.
7. **Остальное без изменений:** 1% на любом возврате, пауза только на ставках, одна ставка на адрес, нет функций
   спасения средств, владелец не касается денег игроков.

## Известные ограничения

- **Сдвиг цены меньше `x*` окупается** (см. «Правило глубины»); правило ограничивает выигрыш, но не отменяет его.
- **Новые возвраты при естественной просадке глубины** в окнах; частота не измерена.
- **Единственный LP на проигрывающей стороне** может превратить раунд в возврат (99% вместо 0).
- **Кипер обязан успевать** к `keeperDeadlines`; иначе REFUND на оживлённом пуле.
- **Ставки видимы,** крупная поздняя ставка забирает исполнение у своей стороны (V3-8); реферер - любой мёртвый адрес
  (V3-9).
- **Гейт 50 WETH и кольцо 900** резко сужают круг пулов (5 из 292 новых в сутки по суточному скану).
- **Отсрочка 24 ч** остаётся только для пула, который не читается совсем (сбой `observe`).
- Пыль и невостребованное не выводятся; контракт неизменяем; только WETH; лимит расходов кипера контрактом не
  измеряется.
- Размер контракта 20 002 байта, запас до EIP-170 4 574.

## Что осталось нерешённым

1. **K.** При 2500 сдвиги до 3.9% на 1%-м пуле окупаются. Большее K - меньше пулов. Нужно продуктовое решение: какой
   остаток манипуляции допустим и сколько пулов нужно.
2. Параметры развёртывания: кап 1, пауза 300, окно 300, K 2500, `minBank` 0.02, `costAllowance` 69 692 gwei, ставка
   0.005-0.04, длительность 300 с.
3. Частота возвратов из-за просадки глубины в окнах на реальных пулах.
4. Повторная проверка аудитором этой редакции.
5. `README.md` и `DECISIONS.md` папки не обновлены (правило работы - только новые файлы).

## Что аудитору смотреть в первую очередь

1. **`PoolRoundOracle.windowDepth`:** разность накопителя с переполнением, среднее гармоническое, цена среднего тика,
   чтение нулевой разности как нулевой глубины.
2. **`_addStake`:** порядок проверки гейта и банка, что ставка на большую сторону не обходит правило во вред.
3. **`fixStrike` и `settle`:** порядок REFUND-ветвей (кольцо, глубина, спред), то, что спот-ликвидность больше не
   влияет, и что раунд с тонким окном не может быть решён.
4. **`_referrerOf`:** ассемблер, лимит газа, обнуление рабочей памяти.
5. **`delistIfBelowGate`:** никто не может снять здоровый пул; зависимость гейта от текущего `minBank`.
6. **`keeperDeadlines`:** формула против поведения кольца Uniswap (одна запись в секунду).
