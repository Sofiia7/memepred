# Кипер раундов PoolRounds (интерфейс v3 после повторного аудита)

Дата: 2026-09-30. Кипер для контракта из [`ROUNDS-CONTRACT.md`](ROUNDS-CONTRACT.md), разделы «Интерфейс v3» и
«Правило глубины». Код: `backend/src/rounds/`. **По умолчанию выключен.** Контракт не развёрнут ни в одной сети, поэтому
кипер проверен тестами и прогоном на локальном anvil (ниже). Ни одной транзакции в Robinhood Chain, Base или другую
публичную сеть не отправлялось.

## Что делает и чего не делает

Работа проекта (газ платит кошелёк кипера):

| Когда | Вызов | Жёсткий срок |
|---|---|---|
| с `strikeEnd`, раунд активирован | `fixStrike(roundId)` | `fixStrikeBy` из `keeperDeadlines(roundId)` |
| с `settleAt` | `settle(roundId)` | `settleBy` из `keeperDeadlines(roundId)` |
| с `settleAt + 24 ч` | `settle(roundId)`: REFUND без чтения пула | нет |
| `feesAccrued` выше порога | `withdrawFees()` | нет |
| листингованный пул ниже гейта | `delistIfBelowGate(pool)` в пределах суточного бюджета | нет |

**Сроки кипер не считает, он их читает.** `keeperDeadlines(roundId)` отдаёт `(fixStrikeBy, settleBy)`: последние
секунды, до которых окно гарантированно читается даже на пуле с наблюдением каждую секунду. При значениях по умолчанию
это `strikeEnd + 599` и `settleAt + 839`, для раундов 900 с - `settleAt + 719`. Позже на оживлённом пуле вызов
проходит, но раунд уходит в REFUND с комиссией 1%. Сроки читаются один раз на раунд вместе с `roundTimes` и
проверяются на здравый смысл: не раньше `strikeEnd` и `settleAt`. `settle` без зафиксированного страйка читает и окно
страйка, поэтому его срок - меньший из двух.

Чего кипер не делает: не создаёт раунды (`roundId = pool << 96 | T << 64 | k` вычисляется), не ставит и не забирает
за игроков и **ничего не платит за неактивированные раунды**: книга окончательна в `closeAt`, такой раунд выбрасывается
из списка в `closeAt` без единого пробного вызова, игроки забирают ставки через `claim`.

Пробный вызов (`eth_call`) идёт перед каждой транзакцией. Ошибки контракта разбираются по имени:
- `AlreadySettled`, `NotActivated`: раунд выбрасывается.
- `StrikeAlreadyFixed`: запоминается.
- `PriceUnavailableNow`: повтор на каждом тике бесплатно. После повторного аудита это только сбой чтения пула:
  нулевая ликвидность в момент вызова больше не мешает, контракт смотрит глубину в окнах.
- `PoolAboveGate`, `PoolNotListed`: ответы проверки гейта (ниже).
- `PoolTooThin`, `BankTooLargeForPool`: ошибки ставки, киперу не встречаются, но разбираются по имени.
- Неизвестная ошибка: до срока повторяется каждый тик, после срока пять раз подряд - раунд откладывается на
  10 минут (`AttemptTracker`).

**Причины возврата показываются по имени, не числом:** `priced`, `history-gone` (кольцо потеряло окно), `spread`,
`grace` (отсрочка 24 ч), `thin-window` (причина 4: окно держало меньше WETH, чем `банк x depthPerBank`). Лог:
`... settled as REFUND (thin-window)`; здоровье считает возвраты за 24 ч по этим именам.

## Проверка гейта пулов

Раз в `ROUNDS_POOL_CHECK_SEC` секунд цепочки (по умолчанию 300) кипер делает пробный вызов `delistIfBelowGate(pool)`
по каждому листингованному пулу. Формулу гейта кипер не копирует, отвечает контракт:
- откат `PoolAboveGate`: пул в порядке;
- откат `PoolNotListed`: пул уже снят, кипер его забывает;
- успех: пул ниже гейта (глубина WETH меньше `gateDepth()` или кольцо меньше `minCardinality`).

Такой пул кипер снимает сам:
- как routine-работу: действуют потолок комиссии и суточный routine-бюджет `gasGuardInstance`;
- в пределах собственного суточного бюджета `ROUNDS_DELIST_DAILY_BUDGET_ETH` (по умолчанию 0.001 ETH): худший случай
  бронируется до отправки и выравнивается по квитанции, как у раундов;
- проверка идёт в конце тика и срочные вызовы не задерживает.

Снятие останавливает только новые ставки, открытые раунды доживают (тест `delists a pool below the gate..., while its
open round still settles`). `bet` сам проверяет гейт, поэтому пул, оставшийся в списке из-за исчерпанного бюджета, ставок
всё равно не берёт. Снятие здесь - наведение порядка, а предупреждение `rounds-pool-thin` говорит, что оно ждёт или
только что случилось.

Какие пулы листингованы, кипер узнаёт из событий `PoolListed` и `PoolDelisted` и из пулов раундов (раунд открывается
только на листингованном пуле). Список хранится в Redis (`rounds:<адрес>:pools`).

## Как включить

В окружение процесса кипера (тот же, что для старых рынков, `CHAIN_PROFILE=rhc`):

```
ROUNDS_ENABLED=true
ROUNDS_ADDRESS=<адрес PoolRounds, строка POOL_ROUNDS=... из вывода DeployPoolRounds.s.sol>
ROUNDS_START_BLOCK=<блок развёртывания PoolRounds>
```

Нужны уже существующие `KEEPER_PRIVATE_KEY`, `REDIS_URL`, `RHC_RPC_URL` (или публичный RPC по умолчанию). Без
`ROUNDS_ENABLED=true` модуль раундов даже не загружается (`keeper/index.ts`, динамический импорт за
`roundsEnabled()`), и кипер старых рынков работает побайтно как раньше. `ROUNDS_START_BLOCK` важен и для пулов: без
него первый запуск не увидит `PoolListed` старше окна `ROUNDS_LOOKBACK_BLOCKS`.

**Отказ при старте.** Если `ROUNDS_ENABLED=true`, но адрес пустой или кривой, нет ключа кипера или
`ROUNDS_INTERVAL_MS` вне 1000-10000 мс, цикл раундов не запускается, в лог пишется
`[rounds] ROUNDS_ENABLED=true but not started: <причина>`, остальные циклы кипера работают. Раз в минуту в Redis
кладётся снимок с этой причиной, и `/health/deep` отвечает `rounds-config-invalid` (503), а не молчит.

## Переменные окружения

| Переменная | По умолчанию | Что |
|---|---|---|
| `ROUNDS_ENABLED` | выключено | включает только точное значение `true` |
| `ROUNDS_ADDRESS` | нет | адрес PoolRounds, обязателен |
| `ROUNDS_START_BLOCK` | нет | откуда читать события при первом запуске; без него - `ROUNDS_LOOKBACK_BLOCKS` назад от головы |
| `ROUNDS_INTERVAL_MS` | 5 000 | период тика; **только 1 000-10 000**, иначе отказ при старте (не подмена значением по умолчанию) |
| `ROUNDS_RECEIPT_TIMEOUT_MS` | 20 000 | сколько тик ждёт квитанции (всех сразу), 2 000-60 000 |
| `ROUNDS_POOL_CHECK_SEC` | 300 | как часто (в секундах цепочки) проверять гейт всех пулов, не меньше 30 |
| `ROUNDS_DELIST_DAILY_BUDGET_ETH` | 0.001 | суточный бюджет на `delistIfBelowGate`; `off`: проверять и предупреждать, но не слать |
| `ROUNDS_LOG_CHUNK_BLOCKS` | 100 000 | блоков на один `getLogs` (публичный RPC RHC их отдаёт) |
| `ROUNDS_LOG_OVERLAP_BLOCKS` | 200 | сколько блоков перечитывать за курсором: реплика RPC может отставать |
| `ROUNDS_LOOKBACK_BLOCKS` | 1 200 000 | около 28 ч, только первый запуск без `ROUNDS_START_BLOCK` |
| `ROUNDS_MAX_LOG_CHUNKS_PER_TICK` | 20 | чтобы долгий догон не держал тик |
| `ROUNDS_CONFIRMATIONS` | 0 | насколько отставать от головы при чтении событий |
| `ROUNDS_GRACE_RESERVE_BPS` | 2 000 | резерв под ветку 24 ч, действует только после жёсткого срока (20%), от 0 до 9 000 |
| `ROUNDS_L1_RESERVE_WEI` | 0 | надбавка к худшему случаю на L1; на RHC (Arbitrum) L1 уже внутри `gasUsed` |
| `ROUNDS_FEES_WITHDRAW_MIN_ETH` | 0.01 | порог `withdrawFees`; `off` выключает |
| `ROUNDS_MAX_TX_PER_TICK` | 20 | транзакций за тик; остальное уходит следующим тиком |

Остальные кривые значения не принимаются: предупреждение в лог и значение по умолчанию.

## Правило для жёстких сроков

**Сколько ждёт: ни одного тика.** Как только `fixStrike` или `settle` стали должны, кипер шлёт их на первом же тике по
текущей цене газа. Держат вызов только три вещи:
- пробный вызов говорит, что сейчас нельзя (повтор каждый тик);
- вызов не влезает в бюджет раунда даже по обычной котировке;
- квитанция прошлой попытки ещё не найдена (не дольше 30 с, потом попытка считается потерянной и уходит заново).

**Когда платит с надбавкой.** Ставка `maxFeePerGas` удваивается, если до срока меньше 45 с или прошлая попытка этого же
вызова сорвалась. На Arbitrum списывается базовая цена, а не потолок, поэтому надбавка ничего не стоит, если цена не
прыгнула между котировкой и включением в блок, и защищает именно от этого. Если удвоенная ставка не влезает в бюджет,
она урезается до того, что влезает; отказ только если не влезает даже обычная котировка.

**Сколько может потратить.** До своего срока `fixStrike` и `settle` могут тратить весь `costAllowance` раунда. После
срока - только `costAllowance x 80%`, чтобы осталось на ветку 24 ч. Ветка 24 ч может тратить весь `costAllowance`.

**Пауза после откатов** (три отката подряд, 30 с с удвоением до 5 минут) до срока не действует, после - действует.

**Очередь в тике.**
1. Квитанции, не пришедшие на прошлых тиках, запрашиваются первыми и все сразу.
2. `fixStrike` и `settle` по самому раннему сроку. Первые попытки идут раньше повторов других раундов, вызовы внутри
   срока раньше просроченных.
3. Ветка 24 ч.
4. `withdrawFees`.
5. Проверка гейта пулов.

Все транзакции раундов сначала отправляются подряд, потом квитанции ждутся вместе. Циклы старых рынков идут через тот
же кошелёк и nonce (`sendKeeperTx`), их очередь кипер раундов не переупорядочивает.

## Бюджет газа

**Правило:** всё, что кипер тратит на раунд (`fixStrike` и `settle`, успешные и откатившиеся), не выше
`costAllowance` из снимка этого раунда (`roundView`, копируется контрактом при первой ставке; пол контракта теперь
2e13 wei).

- Транзакция уходит, только если `потрачено + лимит газа x приложенный maxFeePerGas (+ L1-резерв) <= потолок`.
  Проверка идёт внутри `sendKeeperTx`, по реальной ставке.
- Худший случай записывается в трату до отправки и выравнивается по квитанции. При падении процесса трата завышена,
  но никогда не занижена. Отказ отправки резерв снимает, таймаут не снимает.
- Трата по раунду хранится в Redis (`rounds:<адрес>:spent:<roundId>`, 14 дней) и переживает перезапуск.
- **Исчерпание:** если весь `costAllowance` потрачен, кипер вызовов не делает. Раунд остаётся в списке и в здоровье
  (после срока `rounds-deadline-missed`), а `settle` открыт всем: любой игрок может посчитать раунд сам. Кипер
  отпускает раунд, когда видит его рассчитанным, или когда и ветка 24 ч уже не влезает (`allowance-exhausted`).

Лимит газа - по пику, а не по «использовано»:
- не ниже пола: `fixStrike` 150 000, `settle` 260 000, ветка 24 ч 100 000, `withdrawFees` 120 000,
  `delistIfBelowGate` 120 000;
- не ниже 130% от `estimateGas`;
- после отката out-of-gas x1.5 за каждый откат подряд, потолок x3. Серия считается по действию.

Каждая квитанция пишется и в суточные счётчики `gasGuardInstance`: раунды как `critical` (никогда не блокируются),
`withdrawFees` и `delistIfBelowGate` как `routine`.

## Как находятся раунды

`getLogs` по `RoundOpened`, `Bet`, `StrikeFixed`, `RoundSettled` (с исходом и причиной) и по `PoolListed`,
`PoolDelisted`, кусками по 100 000 блоков, курсор, открытые раунды и пулы в Redis. Сроки берутся из `roundTimes` и
`keeperDeadlines` один раз на раунд. Состояние (`roundView`) читается, только когда что-то может стать должным: до
`closeAt` ни разу, дальше один раз на срок.

Каждый ответ `roundView` сверяется с `roundId` и с `roundTimes`, сроки должны идти по порядку. `keeperDeadlines` не
может быть раньше `strikeEnd` и `settleAt`. Не совпало - кипер не действует, `/health/deep` отвечает
`rounds-abi-mismatch`. Состояние после транзакции берётся из квитанции, а не из чтения следом.

ABI, списки событий, перевод `Times`, `RoundView` и `keeperDeadlines` в понятия кипера и имена причин возврата лежат в
одном файле `backend/src/rounds/contract.ts`. `contract.test.ts` сверяет каждый элемент ABI с артефактом forge и
проверяет, что в нём есть `keeperDeadlines` и нет `commit`, `reveal`, `revealWindow`, `Committed`, `Revealed`. После
правок контракта: `forge build`, затем `npx vitest run src/rounds`.

## Здоровье

Кипер каждый тик кладёт снимок в Redis `rounds:state` (TTL 15 минут). Снимок включает:
- все должные вызовы с их жёсткими сроками (до 100, по сроку);
- рассчитанные за 24 ч раунды и возвраты по именам причин;
- состояние гейта пулов.

Здоровье судит сроки на момент запроса.

`/health/deep` (публичный, только код). Пока снимка нет, ответ побайтно прежний. Со снимком:

| Код | Когда |
|---|---|
| `rounds-keeper-stale` (503) | снимок старше 5 минут |
| `rounds-config-invalid` (503) | `ROUNDS_ENABLED=true`, но кипер раундов отказался стартовать |
| `rounds-abi-mismatch` (503) | `roundView`, `roundTimes` или `keeperDeadlines` не сходятся с ABI |
| `rounds-deadline-missed` (503) | должный `fixStrike` или `settle` не сделан, а срок из `keeperDeadlines` прошёл |
| `rounds-settle-stalled` (503) | должный `settle` ждёт час и больше |
| `rounds-deadline-at-risk` (warn) | должный вызов, до срока меньше 45 с |
| `rounds-pool-thin` (warn) | листингованный пул ниже гейта или кипер снял пул за последние 24 ч |
| `rounds-refunds-thin` (warn) | за 24 ч был возврат по причине `thin-window` |
| `rounds-settle-overdue` (warn) | должный `settle` ждёт 15 минут и больше |
| `rounds-over-budget` (warn) | раунд сдерживается своим бюджетом |
| `rounds-behind-chain` (warn) | чтение событий не догнало голову (или `getLogs` упал) |
| `rounds-snapshot-corrupt` (warn) | снимок не читается; сам `/health/deep` от этого не падает |

Код кипера старых рынков, если он красный, идёт первым. `/health` (живость процесса) раунды не трогают.

`/api/rounds/health` (за периметром): `{status:'off'}` без снимка, иначе:
- `atRisk` и `missed`;
- снимок целиком: счётчики раундов по состоянию, все должные вызовы со сроками, самый старый просроченный `settle`;
- `settled24h`, `refunds24h` по именам (`thin-window`, `history-gone`, `spread`, `grace`);
- `pools`: сколько листинговано, какие ниже гейта с глубиной, `gateDepth`, снятые за 24 ч, трата на снятие сегодня;
- трата газа за 24 ч, баланс кипера, `feesAccrued`, длительность тика и период опроса, последняя ошибка.

Сторож (`workers/watchdog.ts`) уже смотрит `/health/deep`. Ни один вызов не случится сам: сроки выполняются, только
пока кипер запущен.

## Что проверено

- **Тесты:** 126 в `backend/src/rounds/*.test.ts`, 125 проходят, 1 (прогон на anvil) по умолчанию пропускается. Весь
  набор бэкенда: 44 файла (43 проходят, 1 пропущен), 564 теста проходят, 1 пропущен, `tsc` без ошибок (до работы над
  раундами: 36 файлов, 439 тестов).
- **Сроки на искусственных часах** (`keeper.test.ts`, «hard deadlines on an artificial clock»). Кипер тикает раз в
  10 с, самый медленный допустимый период, с фазой, при которой первый тик после срока приходит на 9 с позже.
  Подделка пула пишет наблюдение каждую секунду и теряет окно ровно по правилу контракта. Сроки она отдаёт через
  `keeperDeadlines` (кольцо 900: `strikeEnd + 599`, `settleAt + 839`).

  | Случай | fixStrike после strikeEnd | settle после settleAt | Исход |
  |---|---|---|---|
  | обычный режим | не позже 10 с | не позже 10 с | UP |
  | RPC лежит целый тик в момент, когда вызов стал должным | не позже 20 с | не позже 20 с | UP |
  | пробный вызов откатывается 60 с и 90 с | 60-70 с | 90-100 с | UP |
  | откат в цепочке out-of-gas | не позже 20 с | не позже 20 с | UP |
  | 30 раундов разом при 20 транзакциях за тик | не позже 20 с | не позже 20 с | UP у всех |
  | контракт с тесными сроками (кольцо 420: `+119`/`+359`) и сбой RPC | не позже 20 с | | UP |
  | бюджет исчерпан | вызова нет; раунд в списке; за 40 с до срока `rounds-deadline-at-risk`, после срока `rounds-deadline-missed`; игрок вызывает `settle` сам, REFUND, кипер отпускает раунд, здоровье снова зелёное | | REFUND |

  Контрольный случай: первый вызов через 2 с после `fixStrikeBy` на той же подделке даёт REFUND (`history-gone`).
- **Проверка мутацией:**

  | Сломанное правило | Упало тестов |
  |---|---|
  | сроки-константы вместо `keeperDeadlines` | 2 |

  | снятие пула без ответа контракта | 4 |
  | нет бюджета на снятие | 1 |
  | нет предупреждения `rounds-pool-thin` | 3 |
  | возвраты не считаются | 2 |

  Мутации прошлой редакции (удвоенная ставка, очередь, пауза до срока, резерв, `fixStrike` до `settle`, период

  - Свой anvil 1.7.1 на 127.0.0.1, байткод PoolRounds после повторного аудита.
  - `Params` с `depthPerBank` 2500 (кап 1, пауза 300, окно 300), `minCardinality` 900, `gateDepth` 50 ETH.
  - Стенд-ин `PoolRoundMockPool` с историей ликвидности (1e9 ETH). Пять пулов прошли гейт `listPool`.

## Что не проверено и осталось

1. **Ни одна настоящая сеть.** Не проверены газ L1 (около 13 000 на транзакцию на RHC), настоящий пул Uniswap с его
   кольцом и концентрированной ликвидностью, публичный RPC, реальное время квитанций. Газ `delistIfBelowGate` на
   настоящем пуле не мерился (пол лимита 120 000 взят с запасом). Перед включением: тестнет 46630, цикл со сверкой
   газа и опоздания по квитанциям.
2. **Застрявшая транзакция.** Если отправка принята, а квитанции нет 30 с, кипер шлёт вызов заново на следующем
   nonce. Если первая действительно застряла, вторая встанет за ней. Вытолкнуть застрявший nonce умеет только
   `sendKeeperTx`, и только по ошибке отправки.
3. **Общий кошелёк.** Циклы старых рынков шлют через тот же nonce; кипер раундов не может поставить свои вызовы
   раньше их транзакций.
4. **Счётчик возвратов** живёт в памяти процесса. После перезапуска он собирается заново из событий, и при первом
   запуске с окном назад в «последние 24 ч» могут попасть более старые расчёты.
5. **Redis-хранилище** проверено на подделке node-redis, не на живом Redis. Запуск кипера целиком с
   `ROUNDS_ENABLED=true` не делался (нужны Postgres и Redis).
6. **Параметры** не сверены с живыми ценами газа RHC: `costAllowance` 69 692 gwei, резерв 20%, полы лимитов, надбавка
   x2, порог 45 с, бюджет снятия 0.001 ETH в сутки.
7. Индексатор, фронтенд и монитор инварианта под PoolRounds не написаны; кипер их не заменяет.
