## Как проверено, не разворачивая ничего

`scripts/rhc/rounds-gate-probe.sol` компилируется forge во временную папку (в `contracts/` ничего не пишется) и
выполняется как **init code в `eth_call` без поля `to`**. Узел исполняет конструктор на одноразовой копии состояния
и возвращает результат; состояние выбрасывается. Внутри вызова зонд:

1. разворачивает `ReferralRegistry` и `PoolRounds` с параметрами `DeployPoolRounds.s.sol` по умолчанию и связывает
   их, как скрипт. Параметры не записаны в зонде: `rounds-gate-check.mts` читает их из исходника скрипта
   (`vm.envOr(...)`) и передаёт в конструктор зонда; сейчас это кап 1, пауза 300, окно 300, `depthPerBank` 2500,
   ставка 0.005-0.04, `minBank` 0.02, `costAllowance` 69 692 gwei. Гейт (`gateDepth`, `minCardinality`) зонд
   читает у развёрнутого внутри вызова контракта;
2. для каждого пула читает входы гейта и вызывает `listPool` от имени владельца;
3. делает то, что у стенд-ин пула может сделать кто угодно: `setCardinality(minCardinality)`, затем `setLiquidity`
   на глубину, которую шаг `standins` даёт новым пулам (`max(1 000, 20 x gateDepth)` = 1 000 WETH), и после каждого
   шага снова `listPool`;
4. читает `observe()` на окне страйка и проверяет второй массив (`secondsPerLiquidityCumulativeX128`), из которого
   `fixStrike` и `settle` теперь берут глубину, пронесённую окном;
5. мерит газ `observe()` на 2, 3 и 5 точках (чтения `fixStrike` и `settle`).

L1-часть транзакций развёртывания спрошена у `NodeInterface` цепочки (`0xC8`, `gasEstimateL1Component`), цены - у
`ArbGasInfo` (`0x6C`), тоже через `eth_call`.

Гейт текущей версии: глубина WETH не меньше `gateDepth() = max(2, depthPerBank x minBank) = 2500 x 0.02 = 50` WETH,
кольцо не меньше `minCardinality = max(300, 300) + 600 = 900`, история на 300 с, канонический пул фабрики, пара с WETH.

**Ответ: MOONCAT, PEPE и FROGGO гейт не проходят и для раундов не годятся вовсе.**

1. Глубина 40 WETH меньше гейта 50 (`PoolTooThin`), кольцо 300 меньше 900. Оба поправимы на стенд-ине кем угодно
   (`setLiquidity`, `setCardinality`), и после обеих правок `listPool` проходит.
2. Но эти пулы - `MockUniswapV3Pool`, который во втором массиве `observe()` возвращает нули. Текущий `PoolRounds`
   берёт из него глубину окна страйка и выхода, получает 0 и **каждый активированный раунд завершает REFUND (причина
   4, thin)** с комиссией 1% со всех. `listPool` этого не ловит: гейт читает глубину из `slot0` и `liquidity()`, а не
   из окна. Это воспроизведено на anvil (`e2e-local.log`, раунд OLD: пул прошёл листинг, `fixStrike` сразу дал
   REFUND 4, каждый игрок получил 0.0099 из 0.01).
3. Поэтому раундам нужны **новые стенд-ин пулы `PoolRoundMockPool`** (мок, на который перешли forge-тесты): шаг
   `standins` в `scripts/rhc/rounds-deploy.mts`, см. `docs/rhc/ROUNDS-DEPLOY.md`, шаг 2. Демо-пулы трогать не
   нужно; `setLiquidity` на них бессмысленна и только поменяла бы состояние демо.

**Газ «доращивания», если его всё же делать на демо-пуле:** `setCardinality` - 4 265-4 309 газа исполнения (плюс
21 000 базовых и около 7 700 L1, итого около 33 тыс., 0.33 мкETH при 0.01 gwei); `setLiquidity` того же порядка. Не
нужно по пункту 2.

**Газ чтения на демо-пулах растёт с каждой записью цены** (решение 21 в `DECISIONS.md`): на MOONCAT с 48 записями два
`observe` страйка стоят 204 тыс. газа против 8.5 тыс. на пуле с одной записью. Soak продолжает добавлять записи
(последняя в 02:17 UTC 30.09, по одной на пул в час).
