# Robinhood Chain: обязательные launch-gates

Обновлено 15 сентября 2026, после аудита того же дня и первого прохода
исправлений по нему (см. `review-2026-09-11.md` - что нашли, и историю
коммитов этой ветки - что из этого закрыто). Этот список отделяет три разных
состояния, которые легко перепутать: написано в коде, проверено тестами,
проверено на реальной цепочке. Ни один пункт ниже не является "готово к
mainnet" сам по себе - только вместе с разделом "До mainnet-пилота".

## Сделано в коде и проверено тестами (15 сентября)

Всё ниже прошло через forge/vitest и, где отмечено отдельно, через
`scripts/check-migrations.mjs` против Postgres-в-WASM. **Ничего из этого не
передеплоено на тестнет 46630** - действующий тестнет всё ещё на коде коммита
`6009d53`, ниже раздел "Что не отражено на живом тестнете" об этом отдельно.

- RHC-форма читает `spotPriceWad` из `PoolOracleResolver`, отправляет обычный
  `placeBet` и использует WETH-границы; approve запрашивается только после
  проверки `PoolMarketFactory.isMarket(address)` на цепочке, а не вслепую по
  адресу из URL. Кнопка ставки корректно переходит в ошибку и позволяет
  повторить попытку после реверта или пропавшей транзакции, вместо того чтобы
  вечно показывать "PLACING BET...". Добавлен путь ETH -> WETH с видимым
  балансом.
- **Регрессия допуска LP исправлена.** После того как `PoolMarketFactory`
  перестала автоматически авторизовать новые рынки в хранилище, `_tryLpMatch`
  всё равно вызывала `tryMatch` без try/catch - как только в хранилище
  появлялись деньги, это ревертило вообще любую недозаполненную ставку на
  неавторизованном рынке, включая обычную заявку в пустой книге.
  `PoolLiquidityPool.tryMatch` теперь отвечает 0, а не ревертит; колбэки
  `onMatchSettled`/`onMatchRefunded` больше не проверяют текущую
  авторизацию, так что снятие допуска с рынка не замораживает уже открытые
  LP-матчи на нём.
- **Резолвер больше не запирает матчи навсегда.** Просроченный дольше
  `SETTLE_GRACE` матч теперь пропускается самим резолвером вместо попытки
  `settleMatch`, которая ревертила и валила всю пачку. Проверка внутренней
  согласованности сравнивает окно с усреднением по последней трети окна, а
  не с тиком за одну секунду - односекундный толчок пула (около 0.0005 ETH
  на пуле 2 ETH) больше не блокирует расчёт навсегда. Проверка против живой
  цены (блокировала расчёт только при попытке рассчитать быстро, то есть
  ровно тогда, когда он должен работать) убрана целиком. Расчёт
  (`resolveOrderbookMatch`/`Market`/`Batch`/`BatchFrom`) теперь открыт для
  любого адреса, не только для кипера.
- **Реферальная комиссия платится по реестру, не по конкретной ставке.**
  Раньше трейдер с уже закреплённым рефералом мог передать другой адрес в
  отдельной ставке и увести комиссию себе - реестр это отклонял, но выплата
  всё равно смотрела на поле ордера, а не на реестр.
- **Лимит LP на трейдера освобождается** при расчёте, ничьей и emergency
  refund, а не растёт пожизненно - на рынке, который живёт вечно, старый
  вариант навсегда закрывал доступ к LP после нескольких расчётов.
- Ничья возвращает обе стороны без комиссии; отдельный match не может быть
  меньше `MIN_MATCH_AMOUNT`. Индексатор теперь понимает `MatchTied`: матч
  помечается рассчитанным, ордера продвигаются в `SETTLED`, `won`/PnL в
  `/api/profile` больше не считают ничью полным проигрышем.
- Создание 60-секундного рынка требует истории для 60-секундного entry TWAP,
  а не только для 30-секундного exit TWAP.
- `PoolLiquidityPool` ограничивает LP-экспозицию одного `feedId` суммарно по
  всем длительностям; pool watcher по умолчанию только готовит кандидата к
  ручному обзору (включая оплату кольца наблюдений - раньше этот платёж шёл
  без учёта того же флага), а settlement keeper тикает раз в 15 секунд с
  газовым лимитом, посчитанным по размеру пачки, а не фиксированным 1.8M
  (пачка от 13 матчей раньше не проходила ни при каких условиях). Новый
  keeper-цикл `refundOverdueMatches` сам вызывает `emergencyRefundMatch` для
  матчей старше 24ч + запас, вместо того чтобы ждать, пока кто-то заметит.
- `RhcFeeDistributor` оставляет 90% protocol fee в treasury reserve и 10%
  рефералу; Base fee split не менялся.
- Устойчивость бэкенда: у пула Postgres появился обработчик ошибок (раньше
  разрыв соединения ронял процесс целиком), миграции идут через один
  выделенный клиент под advisory lock, а не тремя отдельными вызовами к
  пулу.
- Проверка 15 сентября 2026, после этого прохода: 375 forge, 277 backend
  Vitest тестов проходят, `scripts/check-migrations.mjs` проходит против
  Postgres-в-WASM. Frontend и полный набор CI - см. `git log` этой ветки на
  момент чтения; часть фронтенд-находок дорабатывалась после этой записи.

## Осознанно отложено, не является багом в смысле "забыли"

- **К-2, гейт глубины пула.** Проверяет только виртуальный резерв в текущем
  диапазоне на момент создания рынка, не перепроверяет глубину при ставке
  или LP-матче. Нужна более широкая переработка (замер по диапазону тиков),
  которую не стали делать наспех в рамках этого прохода.
- **Р-4, ставка по споту против TWAP входа.** Победитель, читающий текущую
  цену пула против запаздывающего 60-секундного TWAP, статистически
  выигрывает чаще половины даже без манипуляции (см. аудит). Правильный
  фикс требует продуктового решения между несколькими вариантами (окно
  входа после принятия ставки, отказ при большом расхождении, явная защита
  цены для заявок в очереди) и измерения на реальных пулах - не стали
  выбирать между ними без данных.

## Что не отражено на живом тестнете

Тестнет 46630 развёрнут из кода коммита `6009d53`, задолго до всего
перечисленного выше. На нём по-прежнему: комиссия рынков 0 (не 1%), каждый
новый рынок автоматически получает доступ к LP, ничья отдаёт победу DOWN.
Ссылка в `buildathon-application.md` на рынок `0x7Af8...06c2` показывает
именно это старое поведение. Передеплой - решение Софии (нужны свежие ключи
для mainnet-пути и тестнет-газ для повторного прохода), не автоматическое
действие.

## До mainnet-пилота

1. Пополнить и наблюдать RHC treasury gas reserve отдельно от LP средств.
   `RhcFeeDistributor` направляет туда 90% protocol fee, но никакая комиссия
   не заменяет стартовый резерв на период низкого объёма.
2. Утвердить 3-5 токенов по таблице: основной DEX/версия, активный v3/WETH
   пул, доля объёма, глубина по диапазону, свежие swaps, история наблюдений и
   стоимость сдвига цены. Не создавать тонкий v3-пул только ради оракула.
3. Для каждого LP-рынка вручную авторизовать адрес в `PoolLiquidityPool` и
   записать лимит общего риска/причину допуска. Никакой рынок не получает LP
   из факта своего permissionless-создания.
4. Пройти на свежем Robinhood-compatible кошельке: wrap/approve/placeBet,
   частичный fill, tie, claim, refund, emergency refund и возврат из wallet.
   Сохранить tx hashes в `DEPLOYMENTS.md`.
5. Запустить внешний uptime/receipt-monitor. При нехватке газового резерва
   остановить новую LP-экспозицию до того, как она создаст обязательства по
   расчёту; уже созданные матчи должны оставаться приоритетом кипера.
6. Измерить на кандидатах долю `MatchUnpriceable`, spread-отказов, задержек
   сеттлмента и исходов tie. Решение о 60-секундном режиме принимать по этим
   данным, а не по теоретической скорости блока.
7. Новый набор ключей для RHC (деплоер, кипер, минтер бейджей), отдельный от
   ключей Base - текущий `.env.rhc` переиспользует ключи, которые
   `docs/SECRET-ROTATION.md` называет сожжёнными для mainnet. Мультисиг на
   момент передачи прав должен быть контрактом (Safe), а не EOA.
8. Решить архитектуру гео-блока для RHC (свой Cloudflare Worker перед
   RHC-API или проверка на origin) и публичный хост для бэкенда - без них
   нет ни соответствия для США/OFAC, ни внешнего мониторинга.

## Не добавлять в MVP

Собственный терминал, мост, кошелёк, launchpad, v4 price source, farming
points/NFT-награды за оборот и дополнительные collateral currencies. Каждый из
них меняет поверхность риска и не решает ни один launch-gate выше.
