## 3. Контракты

**Закрыто и проверено тестами:** L01 (полоса цены стоящей заявки проверяется при каждом матче, `_tryMatch:475-479`, деление безопасно, все копии ABI `getOrder` в indexer/refundExpired/bot-harness/frontend обновлены); L04 (на выигрыше LP пул получает 0.0198, казна 0.0002, дрейфа учёта нет, потому что `onMatchSettled:452-475` не предполагает 2x); L05 (`multisig()` есть у обеих фабрик, sweep 64 против максимум 3 рынков на пул); A03 (`MatchRefunded` ровно один раз, в том числе на LP-матче); LP-допуск (см. §2); пути refund/claim/tie, `nonReentrant` на всех мутаторах, `MIN_MATCH_AMOUNT`, `maxWithdraw` резервирует открытую экспозицию.

**Открыто:**

1. **L02, P1 для живых пулов (на тестнет-стенде не воспроизводится).** `PoolOracleResolver.sol:306-309`: проверка согласованности сравнивает 60-секундное и 20-секундное среднее, оба заканчиваются на `settleAt`, то есть после дедлайна оба уже история, и провалившееся сравнение никогда не изменится. Порог: шаг цены больше ~3.06% за 20 с до дедлайна, ~4.1% за 30 с, ~6% дрейфа за последнюю минуту. Дальше кипер каждый тик эмитит `MarketRefunded(market, "oracle spread too high")` (ничего не возвращая, обработчика у бэкенда нет), через 24 ч `emergencyRefundMatch` отдаёт обе ставки, победитель не получает ничего. Доказано тестом (шаг +3.5% за 20 с до дедлайна на 300-секундном рынке: пропуск в +1 с, пропуск в +3600 с при успокоившейся цене, `MatchUnpriceable` в +24 ч). Что делать: после N неудачных попыток перепривязывать окно к первому более позднему, которое проходит (или убрать проверку: комментарий `ANCHOR_FRACTION` сам говорит, что манипуляция невыгодна), переименовать событие в `MatchSkipped`, в UI писать «заблокировано до settleAt + 24 ч», до демо замерить частоту срабатывания на реальных пулах. Текст RiskGate «расчёт откладывается, пока цена не вернётся» обещает обратное.
2. **Реальный дедлайн кипера, P2.** `MIN_CARDINALITY = 300` (`PoolMarketFactory.sol:87`), окна 30/60/180 с. Пул, пишущий по наблюдению в секунду, хранит 300 с истории: расчёт должен состояться за 270 с (рынок 60 с), 240 с (300 с), 120 с (900 с) после `settleAt`, иначе `OLD`, `MatchUnpriceable` и те же 24 ч. Простой кипера дольше 2-4 минут запирает все открытые матчи; замеренный всплеск газа длился четыре минуты, а `PoolOrderbookMarket.sol:85-88` предполагает, что кипер «переждёт всплеск». Что делать: требовать кардинальность не меньше `2*window` с запасом (или 600) для 900-секундных рынков, алерт на возраст готового матча больше половины запаса.
3. **Побочные эффекты L01, P2.** Выкинутая из очереди заявка обратно не возвращается (`_removeAt`, `:475-482`), отмены нет, остаток заперт до `MATCH_TIMEOUT` (`refundExpired:855-878`), а `claim` требует `filledAmount == amount || unmatchedRefunded` (`:765-769`): у частично исполненной заявки выигранная часть не забирается, пока хвост не вернут через 5 минут. Доказано тестом. Что делать: `cancelOrder` для собственного неисполненного остатка и/или `claim` накопленной выплаты при открытом хвосте; в UI состояние «цена ушла из вашей полосы, остаток вернётся через 5 мин».
4. P3: копии ABI `getOrder` в `backend/scripts/live-cycle.mts:84` и `rhc-bot-harness.mts:117-121` без двух новых полей (безвредно, читают по имени или по младшим индексам). Неограниченный проход головы очереди в `settleMatch`/`emergencyRefundMatch` (`OrderbookMarket.sol:886-893`, 182 724 газа при 200 рассчитанных позади). `FeeDistributor.deauthorizeMarket` ломает расчёт всех матчей рынка (`distributeFee` требует допуск; нужен try/catch). Снапшот комиссии на вечных рынках делает таймлок недостижимым (нужен `syncFee` по аналогии с `syncMultisig`). После L05 владелец фабрики через `setMultisig` + `syncMultisig` получает и unpause на всех рынках (на тестнете владелец = деплойер-EOA). Гейт глубины 2 ETH считает виртуальный резерв: позиция в диапазоне ±0.1% показывает 2 ETH за ~0.001 ETH (только документировать). Комментарий `LiquidityPool.sol:466` устарел. Событие `MarketRefunded` резолвера (это пропуск) путается с `MatchRefunded` рынка (это возврат).
5. Тестовая обвязка: `PoolMarketFactory.t.sol` и `L04FeeEconomics.t.sol` подключают базовый `LiquidityPool`, а деплой ставит `PoolLiquidityPool`. Переключить и добавить регрессию «неавторизованный рынок + депозит в LP + placeBet проходит».

**Открыто:**

1. **Регрессия A08, P1 на живом рынке.** `resolveKeeper.ts:250-263, 351-353, 396, 404`. Итерация 0 читает окно 0, видит застрявшую голову и прыгает на `lastOffset`; следующие итерации читают пустые окна и на каждом делают `offset += 25`; в конце тика сохраняется `lastOffset = resume + 175`. Каждый тик прибавляет до 175 позиций (700 в минуту при 15-секундном цикле). Новый матч, дозревший позади прыжка, не читается никогда: итерация 0 всегда видит застрявшую голову, прыжок всегда уходит дальше него. Он рассчитается только когда `refundOverdueMatches` уберёт голову (settleAt + 24 ч 10 мин). Именно тот класс проблемы, который A08 должен был закрыть. Что делать: сохранять только конец подтверждённо застрявшего префикса (обновлять внутри ветки `wouldSettle === 0n`), не двигать его на пустых окнах, при пустом окне в точке прыжка откатываться на `stuckAt + step`; тест на сам цикл, а не только на `nextStuckOffset`.
2. **Шесть старых рынков, P1 для демо.** `GET /api/markets` (`markets.ts:28-34`) отдаёт их без фильтра по фабрике, они первые в списке по `open_time`; фронт на них пишет «NOT A REAL MARKET». У таблицы `markets` нет колонки фабрики. Минимум: `UPDATE markets SET status = 'CLOSED'` для всех, кроме рынков новой фабрики, и `status <> 'CLOSED'` по умолчанию в списке; надёжно: миграция 008 с `factory_address`, запись в `indexFactory`, фильтр в `/api/markets`, `activeMarkets`, `pendingMarkets`, `rhcPriceRecorder`.
